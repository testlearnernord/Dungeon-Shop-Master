# Dungeon Shop Master — contributor and AI working contract

This is the compact, **current** instruction file for developing Dungeon Shop Master through ChatGPT and GitHub. Runtime and CI claims were refreshed on 22 November 2026 through merged #322; current strict inventory schema is Alpha v36. The earlier Great Cleanup evidence remains in [CLEANUP_AUDIT.md](docs/CLEANUP_AUDIT.md), but it is a historical snapshot. Always verify the **latest** `main`, open PRs and GitHub Actions before editing.

## Source of truth and status words

1. **IMPLEMENTED:** confirmed in current source, relevant tests and/or runtime; code wins over old prose.
2. **PARTIAL:** a working vertical slice exists but its stated release acceptance or coverage remains open.
3. **PLANNED:** approved direction, not implemented merely because the design document says so.
4. **OPEN:** not decided; do not declare canon or choose an unrequested mechanic.
5. **REJECTED / HISTORICAL:** intentionally excluded, superseded or no longer current. Git history preserves prior details.

Read [README](README.md), [Architecture](docs/ARCHITECTURE.md), [Game Bible](docs/GAME_BIBLE.md), [Roadmap](docs/ROADMAP.md) and the affected specialist contract. Inspect **actual modules, callers, tests and asset paths** at the current commit. The latest explicit owner instruction beats an older document, but update the affected documents in the same PR. Never assume an old chat, screenshot, proposed PR number or generated AI summary is the repository state.

## Unbreakable runtime invariants

- **One authority:** `GameState` / `GameStore`, `worldClock.ts` and validated committed world events own gameplay. 20 world ticks per game minute, 50 ms per tick. Shop, exploration and battles progress on this same persisted timeline; sleeping alone closes a day. UI, Babylon scenes and animation cannot award loot, income, heal, advance hero decisions or determine RNG.
- **Combat:** ordinary LIVE fights, the actual Floor-10 Temporary-Party Cave Troll, and developer V/Combat Lab use the authoritative `groupCombat.ts` 60-Hz motor (with `combatEncounter.ts`). `sharedBossCombat.ts` also retains an isolated old single-hero training/recording adapter; BossReplay-v1 conversion and `arenaCombatMotion.ts` are compatibility or presentation paths, not the new Floor-10 game-rule authority. Do not remove real signature grabs, throws, lava, stagger, dodge, parry, multi-hero/multi-monster fights or recorded outcomes.
- **PR #233 safeguard:** Combat Lab records compact **10-Hz checkpoints**, but uses `developerCombatPresentation.ts` to interpolate rendered poses between *committed* frames at browser refresh speed. Never revert presentation to discrete 10-Hz pose painting or tie motor steps to display FPS. Rendering can interpolate spatial presentation but must not predict damage.
- **Viewers and replay are read-only:** abstract floor LIVE maps display committed heroes, parties, site and combat projections; heavy 3D opponents and projectiles load only on opt-in arena. LIVE hero/fight locators, camera and concrete-item inspector observe saved state without changing AI, HP, time, loot or encounter results. Historical replays use immutable committed frames and a separate playback clock.
- **Knowledge boundary:** the shop Board and roster use `liveBoardProjection.ts`, not hidden dungeon state. Offscreen death warnings may communicate only approved magical signals; unobserved HP, secret opponents and unearned outcomes remain hidden.
- **Commerce:** buyers physically acquire and reserve goods; unpaid carts are not revenue. Only real cashier confirmation pays, credit creates debt, expiry yields true walkouts. Concrete dungeon loot belongs to one adventurer and transfers into Galvik's bag only after a paid `hero-buyback`; its `cost` is an expense, not sale revenue. Never grant phantom money, stock, consumables or duplicated loot. Customer locomotion, service claims and checkout must survive save/reload and furniture relocation.
- **Shop and heroes:** player runs the shop, not adventurer movement/combat commands. No hunger/starvation mechanic. Death results from actual HP damage. Shop departure must be physically confirmed before two complete off-duty days begin; no free recovery.
- **Save and reproducibility (OWNER-LOCKED): NO SAVE MIGRATIONS during Alpha.** Current code uses **`SIMULATION_VERSION = 37`**; v35 and older Alpha campaigns are rejected outright, with **no migration/adapters**. Both old LIVE and non-LIVE Floor-6 solo boss dispatchers were deleted; only the Floor-10 party boss can change an authentic LIVE boss result. The obsolete Solo-F6 event contracts, two-gate traffic and non-LIVE day motor are retired. All ordinary Floors 1–9 require hero status `"exploring"`, while `"expedition"` belongs only to the genuine Floor-10 party boss. Reject obsolete state shapes; on a further breaking schema cleanup use one canonical design and **require a new game**. Explicitly reject unsupported old saves, never silently misread them. Test exact Save/Load determinism **within the current new format**, not cross-version imports. Movement takes 200 world ticks (10 unpaused seconds). The one physical portal and unbuildable clearances are owned by `shopPortal.ts`; blueprint preview, persisted furniture and NPC traffic must use that same geometry. Mined 1m stone/floor cells use `caveSurfaceProjection.ts` world-aligned UVs shared with the original cave, cellar and viewer.
- **Presentation quality:** the historical Floor-6 Troll *arena's* authored intro, music, boss HUD, animations and cinematics remain the quality reference for the current Floor-10 Cave Troll and all fights. Monsters may differ in abilities and art; ordinary encounters must not regress to cheap presentation. Experimentation in `V` remains isolated.
- **PR #234 audio:** `gameSfxSamples.ts`, `sfxCatalog.ts` and `groupCombatSfx.ts` map 21 Ghoul WAVs and 11 Troll MP3s through existing mixer/mute, cue filtering and spatial playback. Sounds never drive combat; seek/repaint cannot replay old hits. No regenerated or substituted approved sounds.
- **Assets:** both `predev` and `prebuild` require source GLBs and scripts under `tools/asset_generation/`. The Troll Grab/Throw GLB is a **required** generator input now archived byte-for-byte under `assets/tripo/source/`; never delete it merely because only generated combat GLBs load at runtime. See [Asset Ownership](docs/ASSET_OWNERSHIP.md) for the confirmed B1 removal of a byte-identical *music* duplicate; the served original bytes remain. Keep the GitHub Pages Vite base path correct. No LFS conversion, Git-history rewrite or destructive asset cleanup without separate authorization.

## Workflow and required verification

1. Fetch `main`, open PRs, head commits and relevant tests. Create an isolated branch; explain scope, known risks and explicit non-goals.
2. Change the **smallest existing owner** that solves the problem. Avoid architecture-by-abstraction, duplicate engines, surprise UI redesigns and mutations in projections.
3. For public asset moves and generated GLB changes, run `npm run build` then `npm run verify:pages` to validate the final deployable `dist/` folder, not just the source `public/` tree. Before proposing a code deletion, run `npm run audit:modules`; inspect the static graph, computed-import warnings, real callers and related tests. **Test-only or unreferenced does not itself mean safe to delete.** Test the affected pure rules with unit tests; for camera, Babylon, sound, placement and live/save flows, use targeted Playwright and real browser checks. Run `npm run build` and affected targeted tests for code edits; run `npm run test:unit` for broader gameplay changes. PR CI runs `npm run test:unit:core` and one curated **Browser core smoke** job. The full unit suite and all long browser checks remain available in the manually dispatched **Full browser regression**. See [CI Policy](docs/CI_POLICY.md).
4. Report actual commands, CI conclusion and human-only acceptance gaps honestly. A green CI does not prove audible mixing, real-device FPS, animation quality or overall gameplay balance.
5. Review the living docs that changed behavior: [Game Bible](docs/GAME_BIBLE.md), [Architecture](docs/ARCHITECTURE.md), [Roadmap](docs/ROADMAP.md), [UI](docs/UI_DESIGN_SYSTEM.md) and specialist contracts. **Replace** old claims instead of appending a new PR log.
6. Merge only with explicit owner authorization (including standing approval in the active task), green required checks and no unsafe conflicts. Otherwise leave the PR open with checks, follow-ups and risks visible.

## Scope and design decisions

V.003 remains a **release target** (in-game HUD still says V.002), while V.004 Alpha systems are already merged. **Ordinary dungeon Floors 1–9**, the separate cursed shop realm and shared normal shop threshold, the **Floor-10 2–3-member party boss**, bounded class progression, smarter paid shopping, real loot, buyback, the LIVE Board/Feed, archive, shop cellar and pond are implemented. Hero floor positions now distinguish `"shop"`, `"away"`, `"transit"` and actual Dungeon Floors 1–10; numeric Floor 4 remains exclusively a real dungeon level; the gate is only `portal` and the Boss Pass is already canonical. Floor-7-only solo expedition statuses and their test wrapper are retired in #321 without migrations. The legacy abstract loot counter is retired in the Alpha v36 cleanup: only individual `inventory.finds` contain sellable dungeon goods, and only a fresh real chest plus carried goods may motivate a haul-based return. The #323 source-naming cleanup replaces misleading module/type identifiers without changing real floor topology or saves. Canonical Floor-7 storage was already replaced by `dungeonWorlds` in #315. Individually unique authored deep-floor content, new 100-day balance/physical route evidence, real-device acceptance and this cleanup remain open. The transfer-of-the-curse ending, extra shops, forge expansion and wider lore are **not locked canon**. The existing cellar fishing pond is implemented. An all-history video archive and hunger system have been rejected.

No new gameplay features should sneak into a cleanup PR. Classify genuinely active code versus compatibility-only Alpha leftovers using [the legacy audit](docs/LEGACY_OBSOLESCENCE_AUDIT.md), not filename folklore. An incompatible Alpha save may be reset without an upgrade path.


Galvik's World Clock: one wall-mounted movable furniture instance, persisted at `GameState.wallClock`, using the canonical P blueprint and wall placement validation. Its independent spear mesh reads only `GameState.worldClock.tick` through `worldClockFace`; never invent another scheduler or modify the sleep-only day boundary.
