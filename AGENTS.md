# Dungeon Shop Master — contributor and AI working contract

This is the compact, **current** instruction file for developing Dungeon Shop Master through ChatGPT and GitHub. Runtime contracts include the recovered-goods chest; current strict campaign schema is Alpha v44. The earlier Great Cleanup evidence remains in [CLEANUP_AUDIT.md](docs/CLEANUP_AUDIT.md), but it is a historical snapshot. Always verify the **latest** `main`, open PRs and GitHub Actions before editing.


**Unified live hero combat contract:** Every monster and boss uses the same `heroCombatAttributes` projection, weapon preparation, hero poise, defense eligibility, collision and roll movement. Enemy abilities, telegraphs, geometry and environment may influence tactical choices, never silently replace a hero's stats or gear. The retired solo preview and its combat/replay adapters are deleted; V opens the production-motor Combat Lab directly. The new checkpoint contract requires a fresh Alpha v44 campaign; v43 and older are incompatible. LIVE, atomic dungeon encounters and V use natural motor outcomes, not the historical 35/90-second audit horizons. Active encounters survive the day boundary. `combatRetreat.ts` owns the shared physical retreat policy; `combatProgress.ts` detects 30 seconds without effective HP or retreat progress and first requests a real retreat. A persistently blocked exit may resolve as an explicitly recorded stalemate. `combatRecording.ts` bounds stored positions, not fight duration, keeping the latest minute at 10Hz and thinning only unusually long historical footage. No claim of final balance or visual acceptance.

All repository documentation, issue/PR text, commit messages and new code comments must be in English. Chat language does not change repository language.

## Source of truth and status words

1. **IMPLEMENTED:** confirmed in current source, relevant tests and/or runtime; code wins over old prose.
2. **PARTIAL:** a working vertical slice exists but its stated release acceptance or coverage remains open.
3. **PLANNED:** approved direction, not implemented merely because the design document says so.
4. **OPEN:** not decided; do not declare canon or choose an unrequested mechanic.
5. **REJECTED / HISTORICAL:** intentionally excluded, superseded or no longer current. Git history preserves prior details.

Read [README](README.md), [Architecture](docs/ARCHITECTURE.md), [Game Bible](docs/GAME_BIBLE.md), [Roadmap](docs/ROADMAP.md) and the affected specialist contract. Inspect **actual modules, callers, tests and asset paths** at the current commit. The latest explicit owner instruction beats an older document, but update the affected documents in the same PR. Never assume an old chat, screenshot, proposed PR number or generated AI summary is the repository state.

## Unbreakable runtime invariants

- **One authority:** `GameState` / `GameStore`, `worldClock.ts` and validated committed world events own gameplay. 20 world ticks per game minute, 50 ms per tick. Shop, exploration and battles progress on this same persisted timeline; sleeping alone closes a day. UI, Babylon scenes and animation cannot award loot, income, heal, advance hero decisions or determine RNG.
- **Combat:** ordinary LIVE fights, the actual Floor-10 Temporary-Party Cave Troll, and developer V/Combat Lab use the authoritative `groupCombat.ts` 60-Hz motor (with `combatEncounter.ts`). `sharedBossCombat.ts` supplies the same canonical Cave Troll monster spec for LIVE and the Combat Lab. `combatLabController.ts` owns the V hotkey; no separate solo simulation, replay format or training renderer exists. Do not remove real signature grabs, throws, lava, stagger, dodge, parry, multi-hero/multi-monster fights or recorded outcomes.
- **Ordinary combat and risk:** Ordinary fights use natural outcomes, 0.72-second Ghoul recovery, collision-checked stagger recoil and universal equipped DPS spear timing. Visible authored pack composition, health, gear, experience and traits guide solo hunting and pursuit reactions; actual collisions still enter combat. No alternate simulation. Saved retreat/progress checkpoints belong to the common motor. Use `ghoulPack.ts` and `dungeonThreatDecisions.ts` for visible-pack risk; preserve real LOS and the existing party negotiation. Do not restore the rejected fixed pack attack-spacing experiment. See [current balance evidence](docs/ALPHA_V44_ACCEPTANCE.md).
- **PR #233 safeguard:** Combat Lab records compact **10-Hz checkpoints**, but uses `developerCombatPresentation.ts` to interpolate rendered poses between *committed* frames at browser refresh speed. Never revert presentation to discrete 10-Hz pose painting or tie motor steps to display FPS. Rendering can interpolate spatial presentation but must not predict damage.
- **Viewers and replay are read-only:** abstract floor LIVE maps display committed heroes, parties, site and combat projections; heavy 3D opponents and projectiles load only on opt-in arena. LIVE hero/fight locators, camera and concrete-item inspector observe saved state without changing AI, HP, time, loot or encounter results. Historical replays use immutable committed frames and a separate playback clock.
- **Knowledge boundary:** the magical Board, E/R and compact roster use the same committed `liveRosterCards` projection. Current hero facts are visible to the merchant; detailed map/footage remains explicit observation. Hero perception and historical/event-only disclosure do not inherit roster knowledge; never fabricate outcomes or backfill historical values.
- **Commerce:** buyers physically acquire and reserve goods; unpaid carts are not revenue. Only real cashier confirmation pays, credit creates debt, expiry yields true walkouts. Concrete dungeon loot belongs to one adventurer. Only Iron Ore, Coal and Ghoul Leather are automatically bought at the reachable, open Recovered Goods Chest before normal shopping; the existing `hero-buyback` receipt is an expense and materials enter `shopEconomy.materialStorage`, never the bag. No manual offer API, overdraft, or automatic purchase of other finds. The closed chest is skipped. Other finds remain owned, and only sellable materials count toward the salvage-return threshold. Never grant phantom money, stock, consumables or duplicated loot. Customer locomotion, service claims and checkout must survive save/reload and furniture relocation.
- **Shop and heroes:** player runs the shop, not adventurer movement/combat commands. No hunger/starvation mechanic. Death results from actual HP damage. Shop departure must be physically confirmed before bounded world-tick recovery begins; no free recovery. Real arrivals reset visit-scoped checkout and credit eligibility.
- **Save and reproducibility (OWNER-LOCKED): NO SAVE MIGRATIONS during Alpha.** Current code uses **`SIMULATION_VERSION = 44`**; v43 and older Alpha campaigns are rejected outright, with **no migration/adapters**. Both old LIVE and non-LIVE Floor-6 solo boss dispatchers were deleted; only the Floor-10 party boss can change an authentic LIVE boss result. The obsolete Solo-F6 event contracts, two-gate traffic and non-LIVE day motor are retired. All ordinary Floors 1–9 require hero status `"exploring"`, while `"expedition"` belongs only to the genuine Floor-10 party boss. Reject obsolete state shapes; on a further breaking schema cleanup use one canonical design and **require a new game**. Explicitly reject unsupported old saves, never silently misread them. Test exact Save/Load determinism **within the current new format**, not cross-version imports. Dungeon movement takes 50 world ticks (2.5 unpaused seconds) per hero/party tile and 100 ticks (5 seconds) per monster tile; dungeonPacing.ts owns both intervals. Three consecutive blind perception checks end pursuit (7.5 seconds). World day, combat cadence, recovery deadlines and shop service clocks remain unchanged. The one physical portal and unbuildable clearances are owned by `shopPortal.ts`; blueprint preview, persisted furniture and NPC traffic must use that same geometry. Mined 1m stone/floor cells use `caveSurfaceProjection.ts` world-aligned UVs shared with the original cave, cellar and viewer.
- **Presentation quality:** preserve the authored Cave Troll stage, clips, sound and genuine hit cues across the shared spectator. LIVE entry from World Echoes, map or hero view goes directly to the current committed fight with HUD and camera available. The world continues. Local recorded playback and Combat Lab retain optional cinematics (ordinary 5.2 s, boss 13.5 s); Dungeon Viewer LIVE music requests the corresponding cue with a 1.1 s crossfade, and its manual skip supports both scores. Acoustic and visual acceptance of the final changes remains open.
- **PR #234 audio:** `gameSfxSamples.ts`, `sfxCatalog.ts` and `groupCombatSfx.ts` map 21 Ghoul WAVs and 11 Troll MP3s through existing mixer/mute, cue filtering and spatial playback. Sounds never drive combat; seek/repaint cannot replay old hits. No regenerated or substituted approved sounds.
- **Assets:** both `predev` and `prebuild` require source GLBs and scripts under `tools/asset_generation/`. The Troll Grab/Throw GLB is a **required** generator input now archived byte-for-byte under `assets/tripo/source/`; never delete it merely because only generated combat GLBs load at runtime. See [Asset Ownership](docs/ASSET_OWNERSHIP.md) for the confirmed B1 removal of a byte-identical *music* duplicate; the served original bytes remain. Keep the GitHub Pages Vite base path correct. No LFS conversion, Git-history rewrite or destructive asset cleanup without separate authorization.

## Workflow and required verification

1. Fetch `main`, open PRs, head commits and relevant tests. Create an isolated branch; explain scope, known risks and explicit non-goals.
2. Change the **smallest existing owner** that solves the problem. Avoid architecture-by-abstraction, duplicate engines, surprise UI redesigns and mutations in projections.
3. For public asset moves and generated GLB changes, run `npm run build` then `npm run verify:pages` to validate the final deployable `dist/` folder, not just the source `public/` tree. Before proposing a code deletion, run `npm run audit:modules`; inspect the static graph, computed-import warnings, real callers and related tests. **Test-only or unreferenced does not itself mean safe to delete.** Test the affected pure rules with unit tests; for camera, Babylon, sound, placement and live/save flows, use targeted Playwright and real browser checks. Run `npm run build` and affected targeted tests for code edits; run `npm run test:unit` for broader gameplay changes. PR CI runs `npm run test:unit:core` and one curated **Browser core smoke** job. The full unit suite and long browser checks remain available in the manually dispatched **Full browser regression**. Run long campaign audits only for a concrete balance question or explicit owner request. See [CI Policy](docs/CI_POLICY.md).
4. Report actual commands, CI conclusion and human-only acceptance gaps honestly. A green CI does not prove audible mixing, real-device FPS, animation quality or overall gameplay balance.
5. Review the living docs that changed behavior: [Game Bible](docs/GAME_BIBLE.md), [Architecture](docs/ARCHITECTURE.md), [Roadmap](docs/ROADMAP.md), [UI](docs/UI_DESIGN_SYSTEM.md) and specialist contracts. **Replace** old claims instead of appending a new PR log.
6. Merge only with explicit owner authorization (including standing approval in the active task), green required checks and no unsafe conflicts. Otherwise leave the PR open with checks, follow-ups and risks visible.

## Scope and design decisions

The current Alpha v44 implementation includes the unnumbered shop, ordinary Floors 1–9, unique Floor-10 party boss, cellar/pond/forge, class-specific equipment, world clock and LIVE observation including Galvik's Table handoff. The old solo preview, old save aliases and artificial fight horizons are retired. The HUD label is independent of the save schema. Current open work belongs in [Roadmap](docs/ROADMAP.md) and issue #294, not old PR plans. New lore, monsters and additional tiers require owner approval. No hunger, permanent automatic replay archive or migration.

No new gameplay features should sneak into a cleanup PR. Classify active code versus genuinely obsolete remnants using [the legacy audit](docs/LEGACY_OBSOLESCENCE_AUDIT.md), not filename folklore. An incompatible Alpha save may be reset without an upgrade path.


Galvik's World Clock: one wall-mounted movable furniture instance, persisted at `GameState.wallClock`, using the canonical P blueprint and wall placement validation. Its independent spear mesh reads only `GameState.worldClock.tick` through `worldClockFace`; never invent another scheduler or modify the sleep-only day boundary.

**Threat memory:** `LiveDungeonPlan.threatMemory` holds one last personally observed pack position and observation tick. Evasion and remembered danger use the existing connected walker, not an independent planner or observer-controlled AI. Share observations only within the co-located willing party; a capable party may reassess a solo threat. Remembered LOS exclusion is bounded to 20 map steps (50 unpaused seconds). Do not resume a blocked progression route immediately after LOS breaks; allow safe frontiers, a known upper exit, or a bounded safety wait. Real pursuit and contact still take priority. The current format is v44; no save migration.

**Autonomous boss entry:** `isBossExpeditionCandidate` evaluates living Floor-9 explorers using actual class weapon, armor, experience, HP, supplies, forged gear and personality. `isBossExpeditionParty` requires two or three individually willing heroes; the LIVE motor rechecks readiness, actual saved party, unanimous descent and co-located lower stair at crossing. No merchant-issued permission, mutable flag or scripted audit grants. Combat Lab uses canonical party options without applying the campaign willingness policy; it can deliberately test weak builds. No new combat engine.
