## Current canonical topology / authority

- `CURSED_SHOP_REALM="cursed-shop"` is not one of the normal numbered dungeon maps.
- `OrdinaryDungeonFloor = 1|2|3|4|5|6|7|8|9`; `CAVE_TROLL_FLOOR=10`.
- Real Floor 9 lower stair + a stored 2–3-person valid party, pass checks, HP and scheduled world time starts a Floor-10 boss. The **single saved 60-Hz group motor** owns results and cues. Old Floor-6 solo footage stays as compatible historical data.
- **Status caveat:** the model/schema still uses old shop and gate IDs. The unified *conceptual topology* is ahead of the serialized field migration. The current real-world user interface should not display Floor 5 as the shop or a Floor-6 boss pass.

## Regression and release obligations

1. `npm run build`; `npm run verify:pages`; `npm run test:unit`; curated `npm run test:smoke`.
2. `npm run audit:modules -- --json`: inspect computed imports, unresolved imports, entry-reachable, test-only and unreferenced source modules. **No auto-deletion by name or graph alone.** Static graph cannot prove all dynamic paths or authored binary retention. This review inspected relevant code paths and the Git tree; it did **not** execute a full local graph due to the connector-only execution environment.
3. An old non-LIVE Level-6 campaign event must survive current Save/Load and remain visible in the central Expedition Archive. A real Floor-10 party boss tape must route to the group recorder. Neither view can change gameplay.
4. Current floor 5 and floor 6 exist as ordinary maps, normal stairs and real exits. Floor 10 needs a true group. The old one-door compatibility fields must not grant solo group-boss access.
5. Do not mark issue #294 resolved until new 20/50/100-day runs on *current main*, economic sell-through and real-world browser customer traffic are evaluated. Earlier post-progression runs are useful comparisons, not today's evidence.

**Future change plan:** implement a single versioned shop occupancy + passage abstraction, write fixture migration for old `floor=5` and gate positions, update event and API adapters, then delete old fields and solo-only plumbing **only after** imported saves and repeatable test runs pass. This cleanup intentionally does not pretend that risky migration is completed.
