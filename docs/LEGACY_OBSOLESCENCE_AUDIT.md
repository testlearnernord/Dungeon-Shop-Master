## Current canonical topology / authority

- `CURSED_SHOP_REALM="cursed-shop"` is not one of the normal numbered dungeon maps.
- `OrdinaryDungeonFloor = 1|2|3|4|5|6|7|8|9`; `CAVE_TROLL_FLOOR=10`.
- Real Floor 9 lower stair + a stored 2–3-person valid party, pass checks, HP and scheduled world time starts a Floor-10 boss. The **single saved 60-Hz group motor** owns results and cues. Old Floor-6 solo footage stays as compatible historical data.
- **Current v35 status:** numeric Floor 5 means the genuine ordinary map, not Galvik's shop. The required persisted shop geometry is `shopRoom`; the three unnumbered hero places are `"shop"`, `"away"` and `"transit"`, and real shop traffic owns just one `portal` gate. Historical `level5Room.ts` naming is functional geometry code, not another serialized shop floor. Floor-7-only event types and non-LIVE day solver were retired in #319/#320; #321 removes the remaining ordinary-Floor-7 boss-status exception.

1. `npm run build`; `npm run verify:pages`; `npm run test:unit`; curated `npm run test:smoke`.
2. `npm run audit:modules -- --json`: inspect computed imports, unresolved imports, entry-reachable, test-only and unreferenced source modules. **No auto-deletion by name or graph alone.** Static graph cannot prove all dynamic paths or authored binary retention. This review inspected relevant code paths and the Git tree; it did **not** execute a full local graph due to the connector-only execution environment.
3. Before the breaking cutover, old non-LIVE Level-6 events remain accessible in the existing code. **After cutover, old-format saves need not load or replay.** Current-format Floor-10 party boss tapes must route to the actual group recorder, and viewing may never modify gameplay.
4. Current floor 5 and floor 6 exist as ordinary maps, normal stairs and real exits. Floor 10 needs a true group. The old one-door compatibility fields must not grant solo group-boss access.
5. Do not mark issue #294 resolved until new 20/50/100-day runs on *current main*, economic sell-through and real-world browser customer traffic are evaluated. Earlier post-progression runs are useful comparisons, not today's evidence.

## Alpha v30 — cellar furniture save cut (PR #305)

A new game starts with a single movable, persisted `cellarTable` against the back cellar wall. The authored Tripo GLB is visual-only, while the same P/Blueprint and room-clearance transaction validates actual placement and relocation. Required state is strictly validated alongside `cellarChest`; version 29 and older files are deliberately rejected, without migration. Issue #300 remains open for the unnumbered cursed-shop sentinel, historical event readers, separate Floor-7 storage, old batch day motor, and checkout-API consolidation.

## After v30: retiring Solo-F6 UI replay paths

A saved ordinary Floor-6 exploration must never be classified by `floor===6` as an obsolete solo Cave Troll fight. Expedition Archive routes on `partyBossReplay`, leaving all ordinary 1–9 floors (including Floor 6) on the unified Dungeon Viewer. World Feed, death replay and ledger no longer offer Solo-F6 links. The present v30 Save/WorldEvent type still includes obsolete `level6-*` identifiers and old Solo tape metadata; those are the **next** strict-schema cleanup, not a current boss implementation.

## Strict current-save event cleanup after archive routing

The current strict Alpha-v30 parser rejects retired `level6-departure`, `level6-combat`, `level6-return`, `level7-departure`, `combatOutcome`, and the old one-hero `combatReplay` event payload. Historical names are no longer report, LIVE Board, or archive output categories; a fabricated Solo-F6 event can no longer be loaded to impersonate current gameplay. The old `WorldEvent` interface and isolated boss arena still retain internal tape-facing type/read references pending a separate preview-only refactor; **this is not yet the final removal of all code mentions**. Real `partyBossReplay` and ordinary `dungeonReplay` remain fully supported, with no Alpha save migration.

## PR #310 — single public GameStore cashier boundary

The redundant `GameStore.quoteCheckout()/checkout()` mutation route is retired. Only `GameStore.pickUpShopItem()` (actual reserved shelf stock) and `GameStore.payReservedCart()` (physical till) can pay for ordinary merchandise in the game's public state API. The GroupCombat paid-gear regression now obtains its equipment through these actual paths, rather than a forecast-only direct charge. The standalone `customerCheckout.ts` and historical quote-only fixtures have now been deleted by the subsequent isolated #311 cleanup. No second normal-sale authority remains. No Save schema change or migrations, and no change to real pricing or tip mechanics.

## PR #311 — shadow checkout engine removed

The original direct `checkoutCustomer/quoteCustomerCheckout` module is deleted. Receipt, role-aware needs, purchase/shelf competition, campaign save, and paid-gearing assertions now pay through `pickUpShopItem` then `payReservedShopCart` instead of materializing a forecast into gold and items. A dedicated physical checkout regression suite protects exact-once sale receipts, no revenue at pickup, non-overselling, strict cart validation, no reroll and new-format Save/Load. Genuine commerce paths for unpaid returns, credit, debt, buyback and cashier tips stay intact. No migration or save version bump; Alpha remains v30. The unnumbered shop state, old non-LIVE day simulator and Floor-7 storage architecture remain tracked by #300.

## Alpha v31: shopRoom is the only persisted physical shop geometry

The live shop excavation/placement architecture now uses a single `shopRoom` key everywhere, including the full Save writer/parser, real mining, blueprint preview, furniture collision and NPC navigation. v30 and earlier Alpha campaigns are rejected explicitly and **never migrated**; a v31 save carrying an extra `level5Room` alias also fails strict validation. The underlying `level5Room.ts` room-geometry module stays because it is functional mining code, not a second state. `cellarRoom` and all its independently mined furniture geometry remain untouched. **Not yet solved:** hero shop occupancy `floor=5`, travel `floor=4` sentinel, the non-LIVE day engine, and the separate Floor-7 world key. Those are subsequent scoped PRs, not silently 'fixed' here.

## Alpha v32: true unnumbered shop/away hero locations (#313)

`AdventurerState.floor` is now a discriminated place: real numeric Dungeon Floors 1–10, `"shop"` for Galvik's cursed shop, and `"away"` for genuine off-duty days. Gameplay transitions, buyback, floor-spectator eligibility, Hero Card and saved strict validation agree. Neither a current shop visitor nor a temporarily absent hero can masquerade as an explorer on real Floor 5; numeric dungeon Floor 5 remains playable. Incompatible v31 saves are explicitly rejected with New Game and are not converted. Live portal entry and the single physical doorway remain authoritative. Remaining #300 work: travel/return's historical numeric Floor-4 sentinel, non-LIVE day motor, dedicated Floor-7 storage and historical preview-only types. The region geometry module names are functional, not extra rooms.

## Alpha v33: numerical transit floor removed (#314)

The real Dungeon Floor 4 cannot masquerade as a portal journey: the LIVE returning traveler, the non-LIVE shop-bound visitor and the non-LIVE shop exit all occupy explicit `"transit"` instead of fake numeric Floor 4. Only authentic real-floor explorers occupy numeric Floor 4. The LIVE path still demands actual visited tiles, a saved physical entrance, exactly one scheduled portal event and strict replay/state round-trip, with no fabricated purchases. The isolated non-LIVE day motor now resumes a returning hero at their remembered real depth (or Floor 1 for a fresh visitor) rather than retaining a dead-end transit sentinel. `SIMULATION_VERSION=33` rejects old v32 saves and fake numeric traveler records. **Still unresolved:** eliminate the entire non-LIVE day motor after verifying LIVE parity, unify the separately persisted Floor-7 dungeon world and remove historical source-only aliases. All functional shop/cellar/furniture/Combat Lab and genuine Floor-10 boss behavior must be preserved.

### Alpha v34: one canonical ordinary-floor world checkpoint (#315)

Every genuine Dungeon Floor 1–9, including Floor 7, now uses the same required persisted `dungeonWorlds` collection, keyed by its real numeric floor. There is no independent `level7World`, optional `earlyDungeonWorlds` extension or parallel save authority. LIVE movement, combat settlement, party positions, World Feed observation, spectator and viewer invalidation read the same per-floor collection. The strict validator rejects missing keys, duplicate floors, out-of-range floors and obsolete v33 fields. The current Alpha is v34; v33 and older saves require a New Game, without migration. Historical `level7Replay` event payloads and the independent non-LIVE day engine are **not** removed by this change and remain separate issue #300 work.

### Alpha v35 current-event cutover (#320)

The actual once-per-tick LIVE scheduler is the single runtime motor after #319. The strict current event vocabulary now drops obsolete Solo-F6 departure/combat/return and old Floor-7/day-batch event types; all numbered Floor 1–9 recordings use `dungeonReplay` and the unique Floor-10 party encounter uses `partyBossReplay`. Old Alpha saves are rejected, not converted. Other dated sections above intentionally document earlier historical stages.
